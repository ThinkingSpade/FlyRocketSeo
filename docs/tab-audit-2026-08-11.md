# Tab audit — 2026-08-11

Every project tab audited against Keyword Research, which is the app's
reference standard. Findings carry `file:line` so each one can be picked up on
its own. Everything under **Fixed** is on `main` with CI green; everything under
**Open** is verified but untouched.

The recurring shapes, in order of how much they cost the user:

1. **A failed or in-flight read renders as a confident absence.** The repo has
   fixed this at least four times with explanatory comments and it keeps coming
   back. Worst on metered tabs, where it also invites spend.
2. **A tab states a next step and cannot reach it.** Diagnosis and treatment
   live in different tabs, and the link runs the wrong way or not at all.
3. **A feature re-derives the client's brand from the domain stem** while the
   profile holds the curated spellings. Always wrong the same way, for the same
   clients.
4. **A parameter exists in the destination's schema and the link omits it**, so
   the handoff arrives blind.

## Open

Everything ranked in the original audit is now fixed. What is left came out of
the fixes themselves, and each needs a file or a decision the pass did not own.

### 1. `rewriteOnPageFixes` still writes copy blind

On-Page Fixes is the one feature whose entire output is marketing prose about
the business, and the generator has no idea what the business sells. The client
side now flags suggestions that trip the profile's exclusion lines _after the
fact_; preventing them is server-side. `rewriteSchema` in
`src/serverFunctions/onPage.ts` is `{projectId, ids}` and zod strips extras, so
no client change can reach the prompt. `OnPageAiService.rewrite` already has
`projectId` and can read the profile the way `resolveBrand` reads the project;
`buildPrompt` should carry `offer`, `customer` and `exclusions` — exclusions
matter most, they are what stop "Buy Vending Machines" being suggested to an
operator who only places them.

### 2. Only thin content got a status guard

`missing-title`, `missing-h1` and the rest still match on broken pages, which is
arguably the same double-count that thin content had. Widening it changes
verdict counts more broadly, so it was left as a deliberate decision rather
than folded in.

### 3. Two Rank Tracking loose ends

`AddKeywordsPanel`'s auto-check path is not gated by the new availability check
(it only toasts "Use 'Check Now'"), and "Check rankings" carries no
`meteredActionLabel` while "Update keyword stats" beside it does — so the
cheap action is the one marked as costing money.

### 4. Client Report breadth

Nine features now have a coverage-list entry saying the report has no chapter
for them. Building actual chapters (Rank Tracking, Local SEO, Competitors,
Topic Clusters, Saved Keywords, Trends, SERP, Local Rank Grid, Citations) is a
design change, not a wiring one.

### 5. Five routes still cannot receive context

`opportunities`, `report`, and the three that never came up in a handoff. Add a
schema when something actually needs to link into them; adding one speculatively
just creates an unused parameter.

## Notes for whoever picks this up

- Verdict actions are now the cheapest way to tie two tabs together: add `to` in
  the builder, and `NextStepsCard` supplies `params={{ projectId }}`. The
  builders are pure and have no project in scope — don't thread one in.
- `ON_PAGE_FIXABLE` in `insights/verdicts/audit.ts` is shared by the verdict and
  the issues list so they can't drift about what On-Page Fixes can resolve.
- `resolveBrandTerms(profile, domain)` is the only correct source of brand
  strings. It unions the curated field with the domain stem and ignores an
  unconfirmed AI draft.
- `AnchorHealthCard` takes `brandTerms` as a prop rather than calling a hook: it
  renders through `renderToStaticMarkup` with no query client in its tests.
