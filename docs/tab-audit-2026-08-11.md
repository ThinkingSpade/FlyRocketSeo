# Tab audit — 2026-08-11

Every project tab audited against Keyword Research, which is the app's
reference standard. Findings carry `file:line` so each one can be picked up on
its own. Everything under **Fixed** is on `main` with CI green; everything under
**Open** is verified but untouched.

The recurring shapes, in order of how much they cost the user:

1. **A failed or in-flight read renders as a confident absence.** The repo has
   fixed this at least four times with explanatory comments and it keeps coming
   back. Worst on metered tabs, where it also invites spend.
2. **A tab states a next step and cannot reach it.** Diagnosis and treatment
   live in different tabs, and the link runs the wrong way or not at all.
3. **A feature re-derives the client's brand from the domain stem** while the
   profile holds the curated spellings. Always wrong the same way, for the same
   clients.
4. **A parameter exists in the destination's schema and the link omits it**, so
   the handoff arrives blind.

## Open — ranked

### 1. Competitors: pagination and mode changes are dead clicks

`page` and `mode` are inside the authorization key
(`competitors/competitorsAuthorization.ts:31-32`), so "Next page" and switching
gap mode disable the query and blank the table
(`CompetitorsTabBody.tsx:79` renders "Press Analyze to discover organic
competitors"). Nothing says a page turn costs another metered run.

**Left alone deliberately** — the gating is intentional; what to do instead is a
product decision (auto-authorize, or say "page 2 costs a run"). Worth deciding
before coding.

Related, same file: `KeywordGapOverview.tsx:68/81/94` hardcode `page: 1` while
the table query uses the real page, so any page > 1 issues two metered calls.

### 2. Client Report omits sections silently

`isError` is read for 2 of ~13 queries, and those two messages render only in a
`report-no-print` banner. Every other failure becomes `?? []` and prints as
"never run" — in a PDF that goes to a client. Specifics:

- `reportChapters.tsx:110-114` prints "FlyRocketSEO read this period's Search
  Console data…" unconditionally inside a chapter that can be admitted without
  GSC, directly above a line saying Search Console isn't connected.
- `reportChapters.tsx:206-216` blames a missing GSC connection for a section
  whose data comes from a different query.
- `GscService.ts` returns four distinct failure reasons; the report collapses
  them all to "not connected", so an expired OAuth token reads as never set up.
- Rank Tracking, Local SEO, Local Rank Grid, Competitors, Topic Clusters, Saved
  Keywords, Trends, SERP and Citations have no chapter **and no coverage-list
  entry** — an agency that ran rank tracking all month finds no trace.

### 3. Link Opportunities fans out up to 150 uncached fetches on mount

`LinkOpportunitiesPage.tsx:60-83` builds one `checkLinkPresence` query per
(opportunity × source) with no gating and no user action — capped server-side at
15 × 5, each a full external HTML fetch, each `retry: 1`. Free of credits, but
150 outbound requests against the client's own site on every page open.

### 4. Eight routes cannot receive context

`saved`, `rank-tracking`, `opportunities`, `search-performance`, `links`,
`cannibalization`, `on-page`, `report` have no `validateSearch`. Every "link
exists but arrives blind" finding traces here — e.g. `OpportunityRow.tsx:28-39`
already has a `withQuery` mechanism and two of its three entries have nowhere to
send the query. Fixing these unblocks most of the remaining handoffs.

### 5. The profile reaches 6 of 23 tabs

`ProjectProfileCard` renders on keywords, content, clusters and opportunities.
`keywordFit`/`FitResult` reaches only keywords, clusters and trends. The
highest-value gaps, each a free client-side pass over rows already on screen:

- **Opportunities** mounts the profile _editor_ and then ranks purely by traffic
  (`opportunityModel.ts:85-89`), so an off-offer query tops "what to fix next".
- **Competitors' keyword gap** calls its Missing list "your content roadmap"
  with no fit verdict.
- **Saved Keywords** defines "quick wins" as low KD × volume only, so a list
  full of off-target terms reports a healthy portfolio.
- **On-Page Fixes** generates marketing prose with no idea what the client
  sells — the only feature whose entire output is copy about the business.
- **Rank Tracking's** `KeywordSuggestionStep` pre-selects the top 20 by traffic
  and bills a recurring check on them.

### 6. Smaller verified items

- Overview's "run everything" card links to none of the six tabs it populates
  (`AnalyzeProjectCard.tsx`), despite promising "Each tab then opens showing its
  result".
- Content Optimizer: a restored brief can never load competitor outlines and
  says "No data" for something never requested (`ContentOptimizerPage.tsx:369`).
- AI Visibility / Prompt Explorer: "Recent searches" clears the URL and the form
  but not the results — the query is keyed on state, not the URL.
- AI Visibility: a hardcoded `locationCode: 2840` disagrees with the tracked
  panel on the same page, which uses the project's market.
- Page Explorer: no inbound links from anywhere, and the `"own-pages"`
  suggestion intent exists solely for it with no consumer.
- Site Audit: deleting an audit leaves it visible on five other surfaces
  (cache-key split between `audit-history` and `auditHistory`).
- Site Audit: thin-content double-counts pages already reported as broken.

## Notes for whoever picks this up

- Verdict actions are now the cheapest way to tie two tabs together: add `to` in
  the builder, and `NextStepsCard` supplies `params={{ projectId }}`. The
  builders are pure and have no project in scope — don't thread one in.
- `ON_PAGE_FIXABLE` in `insights/verdicts/audit.ts` is shared by the verdict and
  the issues list so they can't drift about what On-Page Fixes can resolve.
- `resolveBrandTerms(profile, domain)` is the only correct source of brand
  strings. It unions the curated field with the domain stem and ignores an
  unconfirmed AI draft.
- `AnchorHealthCard` takes `brandTerms` as a prop rather than calling a hook: it
  renders through `renderToStaticMarkup` with no query client in its tests.
