# Tab audit — 2026-08-11

Every project tab audited against Keyword Research, which is the app's
reference standard. Findings carry `file:line` so each one can be picked up on
its own. Everything under **Fixed** is on `main` with CI green; everything under
**Open** is verified but untouched.

The recurring shapes, in order of how much they cost the user:

1. **A failed or in-flight read renders as a confident absence.** The repo has
   fixed this at least four times with explanatory comments and it keeps coming
   back. Worst on metered tabs, where it also invites spend.
2. **A tab states a next step and cannot reach it.** Diagnosis and treatment
   live in different tabs, and the link runs the wrong way or not at all.
3. **A feature re-derives the client's brand from the domain stem** while the
   profile holds the curated spellings. Always wrong the same way, for the same
   clients.
4. **A parameter exists in the destination's schema and the link omits it**, so
   the handoff arrives blind.

## Open

The audit backlog is closed. What remains is design work, not wiring:

### Client Report chapters for the nine uncovered features

Rank Tracking, Local SEO, Local Rank Grid, Competitors, Topic Clusters, Saved
Keywords, Trends, SERP and Citations now each carry a coverage-list line saying
the report has no chapter for them, so their absence is legible. Writing actual
chapters is a design change — what a rank-tracking page should say to a client
is a product question, not a plumbing one.

### Five routes still have no `validateSearch`

`opportunities`, `report`, and three others nothing currently links into. Add a
schema when something needs to link in; adding one speculatively just creates a
parameter no caller passes.

## Notes for whoever picks this up

- Verdict actions are now the cheapest way to tie two tabs together: add `to` in
  the builder, and `NextStepsCard` supplies `params={{ projectId }}`. The
  builders are pure and have no project in scope — don't thread one in.
- `ON_PAGE_FIXABLE` in `insights/verdicts/audit.ts` is shared by the verdict and
  the issues list so they can't drift about what On-Page Fixes can resolve.
- `resolveBrandTerms(profile, domain)` is the only correct source of brand
  strings. It unions the curated field with the domain stem and ignores an
  unconfirmed AI draft.
- `AnchorHealthCard` takes `brandTerms` as a prop rather than calling a hook: it
  renders through `renderToStaticMarkup` with no query client in its tests.
